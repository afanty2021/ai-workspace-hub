# Pattern：自引用夹具族

## 一句话结构

夹具输入 = f(常量)，断言期望 = g(常量)：常量漂移时输入与期望同向漂移，测试永绿——锁的是「常量自洽」不是「常量正确」。

## 何时调用

- 写可观测的结构信号：夹具/断言中出现被测模块的常量引用（如 `f"close=1 nav=2 {ump.EXDIV_MARK}"` 构造 note、或期望值由 `ump.X` 算出）。

## 判别式

- 这张卡会改变分析中的哪个判断？——评审测试时对「常量引用」分两类：断言侧引用常量（可接受，值锁另设）vs **夹具输入侧**引用常量（本卡打击对象——输入必须独立于被测逻辑）；再查是否有独立的常量↔字面量对拍组。

## 机制

变异实验 M71/72/75/91 型（改常量）全绿的根因：输入由常量构造，改常量=改输入，断言的相对关系不变。修根两件套：①夹具输入全部改字面量（如 note 构造直接写 "exdiv-repair"）；②新增 ConstantLiteralLockTests——每个关键常量与字面量逐一 assertEqual（ALERT_THRESH_BP==-5.0 等），常量被误改时对拍组先红、定位清晰。对拍组同时充当常量清单的活文档（改值须四同源行+skill+CHANGELOG 同步的提醒挂在断言 message 上）。

## 适用范围

单元测试夹具、集成测试的期望值构造；对「黄金文件」型夹具（golden file 由常量生成）同样适用。

## 失效条件

- 对拍组引入「改常量必须改测试」的同步义务——这是特性（强制自觉），但常量很多时对拍组本身膨胀；只对「改动会改变行为语义」的关键常量设拍（阈值、锚、标记串），展示型常量豁免。
- 若夹具故意参数化测试常量的不同取值（参数化测试），引用常量是设计意图，不适用本卡。
